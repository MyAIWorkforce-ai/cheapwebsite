# Test prompts

A handful of prompts the buyer can try to confirm the bot works
after setup. Pick a mix of easy and hard — the buyer's trust forms
in the first 30 seconds of using the bot, so the first test should
feel like a quick win and the last should show the bot handling
something gnarly.

Replace the example prompts below with 8–12 of your own, then save.

---

## Quick wins (buyer should see immediately)

1. [simple question the bot answers in 1-2 sentences]
2. [another simple one]
3. [a "hello, who are you?" style intro prompt]

## Realistic jobs (what the bot was built for)

4. [a representative task — the kind of thing the buyer actually
    bought this bot to do]
5. [another representative task]
6. [a task that requires the bot to use its knowledge files]
7. [a task that requires the bot to use a tool, if any]

## Edge cases (shows the bot is robust)

8. [a tricky input — ambiguity, incomplete info, weird phrasing]
9. [an off-topic request — bot should politely decline / redirect]
10. [a request that tests a specific rule in the system prompt]

---

If the bot gets 8+ of these right, the buyer knows they got what they
paid for. If it gets most but not all right, that's actually healthy —
no bot should ace every test. If it fails more than 2, something went
wrong in setup; the buyer should re-check steps 2-4 in `SETUP.md`.
